# Use Case 1: Normal vs. Exam-Period Traffic

This subpackage implements Use Case 1 from the ELVIRA evaluation: a comparison of baseline (central-only) vs. proposed (edge-cached) CDN architectures under realistic academic workloads.

### Simulation Overview
The simulation models student requests to a university digital library (books PDFs) using a Zipf-distributed popularity pattern (α=0.9 by default). Traffic is generated by 5 independent "student" containers (one per faculty), each running concurrent HTTP clients that:

- Resolve `elvira.lib` via DNS (controlled by central-manager).
- Fetch a root page and multiple books (1–3 in normal mode, 1–9 in exam mode) with jittered think times.
- Use configurable concurrency (20–30 per faculty), duration (600s default), and think time (1000ms default).

Traffic profiles:
- **Normal semester**: Moderate, steady load (lower concurrency, fewer books per cycle).
- **Exam period**: 2–3× surge with bursty behavior (higher concurrency, more books per cycle).

### Architecture Modes
- **Central-only (baseline)**: All requests hit the central server directly (DNS resolves to central IP).
- **Edge-enabled (proposed)**: DNS resolves to nearest faculty edge node. On cache miss, edge fetches from central and caches locally.

Mode is toggled via central-manager API (`/switch-to-central` or `/switch-to-edge`).

### Key Components
- **Student simulators** (5 containers: student-facultyA–E):
  - Custom Node.js script simulating realistic request patterns.
  - DNS override to use hierarchical resolver.
  - Metrics: total/failed requests, latency.
- **Central & edge managers** (from previous subpackages): Handle routing, caching, metrics.
- **Prometheus + Grafana**: Collect and aggregate metrics across all nodes.

### Metrics Collected
- End-to-end latency (p50/p95).
- Cache hit ratio.
- Origin offload %.
- Total energy consumption (kWh).
- Peak power draw.
- Eco Index (energy per request-hour, adjusted for cache utilization).

### Frontend Interface[](http://localhost:3101)
The React-based dashboard provides live monitoring and control:
- **Topology Diagram**: Visualizes central ↔ edges network with animated packet flows in edge mode; button to toggle DNS mode (disabled during sim).
- **Node Matrix**: Grid of live node cards (central + 5 edges) showing energy, CPU, requests, power, cache usage; click for detailed metrics dialog.
- **Eco Index Card**: Real-time computation of total energy, CO₂, avg cache utilization, requests, and Eco Index (lower = greener).
- **Controls Panel** (right drawer): Start/stop simulation in "normal" or "exam" mode; reset metrics; monitor status.
- **Live updates**: Polls metrics every 5s.

This use case enables direct comparison of energy efficiency, latency, and scalability between centralized and edge-distributed architectures under varying academic loads.
